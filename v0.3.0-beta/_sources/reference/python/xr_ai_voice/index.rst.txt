xr_ai_voice
===========

.. py:module:: xr_ai_voice

.. autoapi-nested-parse::

   Applications configure and register :class:`VoiceAgent` and may route
   concurrent producers through :class:`VoiceAggregationAgent`; media sessions,
   audio framing, and pipeline processors are implementation details.

.. py:class:: VoiceAggregationAgent(*, llm: xr_ai_models.LLMService, prompt: str = _DEFAULT_PROMPT, coalesce_window_s: float = 0.15, queue_capacity: int = 64, max_batch_size: int = 8, max_tokens: int = 192, stream_idle_timeout_s: float = 15.0, participant_idle_timeout_s: float = 60.0, speech_rate_wpm: float = 150.0, minimum_playback_s: float = 0.4, maximum_playback_s: float = 30.0, rewrite_timeout_s: float = 5.0)



   Serialize and coalesce candidate speech independently per participant.

   A lone finite contribution passes through without a model call after the
   short coalescing window. Completed text is finalized downstream immediately,
   while the aggregator independently reserves its estimated spoken duration
   so later updates wait and coalesce instead of building a speech queue.
   Multiple pending finite contributions are rewritten into one response. A
   lone incremental response streams through immediately and uses the same
   scheduling reservation after its final chunk. An urgent contribution
   interrupts the active output.

.. py:class:: VadConfig

   Tuning knobs for the Silero-VAD utterance detector.

   Mirrors the constructor of :class:`xr_ai_vad.VadDetector`. Default
   values match the in-tree samples' current behavior.

   ``stop_probe_after_s`` — cadence in seconds for up to three STT probes of
   the partial audio buffer. This gives STOP commands a fast interruption path
   without replacing final transcription, and lets a configured wake phrase
   be acknowledged before the utterance ends. A phrase-gated utterance can
   make up to three partial STT requests plus the final request. Set to ``0``
   or negative to disable probes.

.. py:data:: VOICE_TRANSCRIPT_TOPIC

   Non-empty final STT results queued for publication before gate filtering.

   Delivery is best effort: the bounded queue drops its oldest pending item on
   overflow, and shutdown discards queued items that have not been published.


.. py:class:: VoiceAgent(*, query_topic: xr_ai_runtime.Topic[xr_ai_interaction.UserQuery], stt: xr_ai_models.STTService | None, tts: xr_ai_models.TTSService, vad: xr_ai_voice.VadConfig, voice_gate: xr_ai_voicegate.VoiceGateConfig, probes: collections.abc.Mapping[str, collections.abc.Callable[[], collections.abc.Awaitable[bool]]] | None = None, ready_file: pathlib.Path | None = None, closeables: collections.abc.Iterable[Any] = (), text_topic: str = 'agent.response', idle_timeout_secs: float | None = None, transport: xr_ai_voice.HubVoiceTransport | None = None, response_capacity: int = 32, text_input: bool = True, participant_joined_topic: xr_ai_runtime.Topic[xr_ai_interaction.ParticipantJoined] | None = None, participant_left_topic: xr_ai_runtime.Topic[xr_ai_interaction.ParticipantLeft] | None = None, interrupted_topic: xr_ai_runtime.Topic[xr_ai_interaction.Interrupted] | None = None, interrupt_on_supersede: bool = False)



   Own voice media lifecycle and bridge runtime input and output topics.

   Startup waits for explicitly supplied ``probes``, such as an inference
   warmup or an application capability dependency, and required speaker ASR.
   Batch STT and TTS health are not polled automatically. Readiness reports
   initialized application transport after those startup requirements, not
   availability of every model endpoint.

   ``voice_gate`` selects speech through its speaker settings. ``stt=None``
   is accepted only with enabled, required speaker ASR; startup then waits
   for that service. Ordinary STT and automatic speaker selection require a
   batch ``STTService``. Missing that dependency raises :class:`ValueError`
   before VoiceAgent allocates media. An injected transport is already allocated
   by its caller, who retains cleanup responsibility if construction fails.

   :meth:`from_models` resolves that dependency from an already-loaded model
   profile and the same voice-gate configuration, without application-side
   backend inspection. The normal constructor accepts explicitly owned clients.

   Accepted queries also return participant-routed UTF-8 display text on
   ``voice.user-query``. Speaker ASR includes its session-local speaker label;
   ordinary STT and typed input use ``User``. This display does not change
   :class:`UserQuery` or require an application subscriber. Delivery uses the
   existing hub transport and retains its backpressure and best-effort semantics.


   .. py:method:: from_models(*, models: xr_ai_models.ModelsConfig, query_topic: xr_ai_runtime.Topic[xr_ai_interaction.UserQuery], tts: xr_ai_models.TTSService, vad: xr_ai_voice.VadConfig, voice_gate: xr_ai_voicegate.VoiceGateConfig, probes: collections.abc.Mapping[str, collections.abc.Callable[[], collections.abc.Awaitable[bool]]] | None = None, ready_file: pathlib.Path | None = None, closeables: collections.abc.Iterable[Any] = (), text_topic: str = 'agent.response', idle_timeout_secs: float | None = None, transport: xr_ai_voice.HubVoiceTransport | None = None, response_capacity: int = 32, text_input: bool = True, participant_joined_topic: xr_ai_runtime.Topic[xr_ai_interaction.ParticipantJoined] | None = None, participant_left_topic: xr_ai_runtime.Topic[xr_ai_interaction.ParticipantLeft] | None = None, interrupted_topic: xr_ai_runtime.Topic[xr_ai_interaction.Interrupted] | None = None, interrupt_on_supersede: bool = False) -> VoiceAgent
      :classmethod:


      Construct voice input from loaded models and voice-gate settings.

      Enabled, required speaker ASR uses the configured streaming endpoint
      without constructing a batch client. Disabled or automatic speaker
      selection constructs the existing ``stt`` model role. Automatic
      selection retains that real batch client for its startup fallback.
      Other arguments and resource ownership match the normal constructor.

      Raises :class:`KeyError` when the selected batch ``stt`` role is absent,
      :class:`TypeError` when it names another model role, and
      :class:`ValueError` for an unsupported adapter or non-positive response
      capacity. Caller-created clients and transports remain caller-owned
      when construction fails.
