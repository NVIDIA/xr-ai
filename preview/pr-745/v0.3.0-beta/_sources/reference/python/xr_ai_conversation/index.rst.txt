.. py:class:: Conversation(llm: xr_ai_models.LLMService, *, context: xr_ai_conversation.ContextManager, instructions: str = '', system_prompt: str | None = None, routing: xr_ai_routing.RoutingAid | None = None, runtime: xr_ai_runtime.AgentRuntime, output_topic: xr_ai_runtime.Topic[xr_ai_interaction.ResponseOutput])



   Application-instructed conversation agent over participant-scoped context.

   The conversation owns its prompt and answer; ``context`` owns what is
   remembered. The caller creates the manager, may share it with other
   agents, registers its ``subscriber()``, and closes it.

   :param llm: Typed streamed language model service.
   :param context: Participant context rendered into each request. The conversation records
       completed exchanges in it and never clears or closes it.
   :param instructions: Application-owned prompt text defining domain, role, tone, and handling policy,
       appended to the system prompt.
   :param system_prompt: Replaces the default general-conversation system prompt.
   :param routing: Concise front-end metadata; defaults to a general conversation description.
   :param runtime: Runtime used to publish answers. The application owns runtime startup and shutdown.
   :param output_topic: Explicit ``ResponseOutput`` topic for routed answers.
       The conversation publishes replies with its routing name as source, the turn ID as request ID,
       and the originating timestamp. It owns stream framing and finalization.
       No default output or query topic is subscribed.

   .. py:method:: admit(turn: xr_ai_routing.AgentTurn, *, focused: bool) -> xr_ai_routing.Admission

   .. py:method:: answer(turn: xr_ai_routing.AgentTurn, *, started: collections.abc.Callable[[], collections.abc.Awaitable[None]]) -> xr_ai_routing.DestinationResult
      :async:


      Publish a routed answer directly to the configured output topic.

      Requires ``runtime`` and ``output_topic``. The answer is a reply to the
      turn's ID. The first nonblank ready chunk awaits ``started()`` before
      publication, and an empty final frame closes a completed, failed, or
      canceled response once opened. Canceled answers publish no further text,
      and a publication failure publishes no further frames. Failures
      propagate after closing the model iterator; the router reports
      failures that occur before the first frame. A successful answer
      returns the complete text as routing context. The exchange joins the
      participant's context only after its final frame is delivered.



   .. py:method:: release(_participant_id: str) -> None
      :async:

      Participant context belongs to the context manager, whose owner clears it.



   .. py:method:: participant_left(_participant_id: str) -> None
      :async:


      Hold nothing for a departed participant; the context manager's owner clears its context.



   .. py:method:: close() -> None
      :async:


      Stop answering. The caller closes the context manager and drains answer streams.

.. py:class:: ContextManager(llm: xr_ai_models.LLMService, *, summary_context_topics: collections.abc.Sequence[str] = (), incremental_context_topics: collections.abc.Sequence[str] = (), dialogue_budget_bytes: int = _DEFAULT_DIALOGUE_BUDGET_BYTES, topic_budget_bytes: int | collections.abc.Mapping[str, int] = _DEFAULT_TOPIC_BUDGET_BYTES, compaction_input_budget_bytes: int = _DEFAULT_COMPACTION_INPUT_BUDGET_BYTES, compaction_prompts: CompactionPrompts | None = None)

   Retain participant-scoped context and render it into prompts for any number of agents.

   Completed dialogue and each configured topic are separate sections with
   their own byte budget. A summary topic keeps only its latest state; an
   incremental topic and the dialogue keep recent entries verbatim and fold
   older ones into a rolling summary written by ``llm``.

   Every method runs on the event loop and none yields between reading and
   writing a participant's context, so a participant's context is never
   observed half-updated. Compaction runs as a background task per section.

   The owner creates the manager, registers ``subscriber()`` with the runtime
   that delivers context updates, calls ``clear()`` when a participant leaves,
   and calls ``close()`` at shutdown. Agents that share a manager use its
   budgets, so those are configured here and not per agent.

   :param llm: Model service that writes compaction summaries.
   :param summary_context_topics: Runtime topic names whose text replaces that source's state.
   :param incremental_context_topics: Runtime topic names whose text appends to that source.
   :param dialogue_budget_bytes: UTF-8 byte budget for completed dialogue rendered into a prompt.
   :param topic_budget_bytes: UTF-8 byte budget for each topic's context rendered into a prompt:
       one value for every topic, or a mapping with a value for each configured topic.
   :param compaction_input_budget_bytes: UTF-8 byte budget for the summary and entries in one
       compaction request; at least half the largest section budget plus 256 bytes.
   :param compaction_prompts: Compaction instructions; defaults to ``CompactionPrompts()``.

   All budgets must be positive. Topic lists contain non-empty names; names
   must be unique within and across both lists.
