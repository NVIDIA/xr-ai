Release migration#

Overview#

Required changes when upgrading from v0.4.0-beta to the checked-out version. main is unreleased. Apply the entries relevant to your application’s SDK usage, configuration, clients, and services.

Changes since v0.4.0-beta#

If upgrading from an older release, first apply Migration from v0.3.0-beta to v0.4.0-beta. Refer to Migration history for earlier guides and apply them in release order.

LLM request defaults#

OpenAICompatLLM now applies adapter.default_extras only when a call omits an optional value. Explicit max_tokens, temperature, tools and output constraints override the corresponding defaults. The selected model, caller messages and method’s streaming mode cannot be replaced by extras. If a profile previously relied on extras overriding those values, move that choice into the call instead. Constraints supplied through extras are validated against endpoint capabilities before transport. OpenAICompatVLM wraps the same client, so VLM profile extras follow the same rules.

Restart Pocket TTS before upgrading#

The Pocket TTS launcher now reuses a listener only when /health identifies service: pocket_tts_server. A running v0.4.0-beta server returns only status: ok, so the updated launcher rejects it and reports that the port is already in use.

Before updating, stop the model stack with the old checkout’s sample command and the GPU profile used to start it. For example, from agent-samples/conversation-example/:

uv run --project model-servers conversation_example_model_servers --stop

For a standalone deployment, stop Pocket TTS through the supervisor that started it. Update the checkout, refresh the service environment, and restart the model stack before workers. Refer to Customizing model servers for model startup and shutdown.
