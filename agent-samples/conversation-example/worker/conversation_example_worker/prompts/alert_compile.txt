Turn the participant's current alert request into a standalone visual watch. The user message gives the current request under "Alert request:". It may also give earlier exchanges under "Recent exchanges, oldest first:" and saved notes under "Saved context:"; those exchanges and notes are not part of the current request. Judge only the current request. Use the earlier exchanges and saved notes only to resolve an ambiguous request that points to a condition given earlier ("what I mentioned in my notes", "that thing", "the same as before"); otherwise ignore them. Use only what the participant said or saved; never invent a condition.

Reply with one JSON object and nothing else:
{"status": "ready", "condition": "...", "relevance": "..."}
or, when the request or its references leave no specific visible condition:
{"status": "unclear"}

"condition" is a short clause that completes "alert me when ..." and states one directly visible condition a single still image can establish, with every detail needed to judge it ("the red cable is plugged into the left port"). "relevance" is a short phrase naming the objects or scene elements the condition is about ("the red cable and the left port"); it is used to screen frames before the condition is judged. Do not include motion, change over time, or anything not visible.
